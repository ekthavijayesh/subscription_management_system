# Development Roadmap

## How to execute this roadmap

Tasks execute in numeric order unless their dependency column explicitly permits parallel work. A task is complete only when its objective/scope is delivered, its acceptance/test evidence is recorded, and its checklist item is checked in `PROGRESS.md`. Expected files are a starting point: inspect before creating them.

**Universal task checklist:** [ ] requirements/assumptions confirmed; [ ] dependency checked; [ ] implementation complete; [ ] authorization/RLS considered; [ ] loading/error/empty states included where UI exists; [ ] tests run and recorded; [ ] docs/types updated; [ ] no secrets/mock/dead controls; [ ] `PROGRESS.md` updated.

## Phase gates

- **Phase 0:** product owner approves requirements, workflows, data design and this roadmap.
- **Phase 2:** migrations apply from zero, generated types are current, and RLS role tests pass.
- **Phase 3:** unauthorized access tests prove guards are not merely visual.
- **Phases 8–13:** financial state changes are transactional, idempotent, logged and tested before dashboard work relies on them.
- **Phase 15:** all test/security/performance evidence is recorded before production setup.
- **Phase 16:** deploy only after a named owner accepts launch risk and rollback process.
